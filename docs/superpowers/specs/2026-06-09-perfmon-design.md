# PerfMon 🚀 — macOS 性能监控与诊断工具 · 设计文档

> 日期：2026-06-09
> 状态：设计稿（待评审）

## 1. 背景与目标

用户的 MacBook Air（Apple M3）出现**间歇性卡顿 + 发热**。排查发现主要诱因：
- 外接 6K 显示器的 HiDPI 缩放渲染导致 WindowServer 长期高占用；
- 内存耗尽、Swap 接近打满，频繁磁盘交换；
- 个别 App（如渲染进程、Telegram）的瞬时 CPU 峰值；
- 系统长期未重启导致资源碎片。

现有工具（活动监视器）只看数据、不给结论，第三方工具偏重或含广告。

**目标：** 做一个**原生、轻量、好看**的 macOS 工具，既能实时监控 CPU/内存/温度，又能**诊断"为什么卡为什么热"并给出可执行的处理建议**，并提供**一键加速**。

**非目标（YAGNI）：**
- 不支持 Intel Mac（仅 Apple Silicon M1–M5）。
- 不做云同步、不做账号体系、不做跨设备。
- 不做磁盘深度清理（只清可重建缓存）。

## 2. 技术栈

- **语言/框架：** Swift + SwiftUI（主界面）+ AppKit（菜单栏、悬浮窗、NSVisualEffectView 毛玻璃）。
- **构建：** Xcode 项目，最低系统 macOS 13（Ventura）起（vibrancy 与 SwiftUI 成熟度考虑）。
- **传感器读取：** 私有框架 `IOHIDEventSystemClient`（读温度），公开 API `host_processor_info` / `mach` 读 CPU、`vm_statistics64` 读内存、`sysctl` 读 Swap/负载。
- **不需要：** sudo、内核扩展、网络权限。

## 3. 视觉风格

- **毛玻璃（Vibrancy）：** 所有窗口使用 `NSVisualEffectView`，半透明 + 背景模糊，随桌面壁纸实时透出。
- **Logo：** 火箭 🚀，渐变方块包裹，用于菜单栏小图标与各窗口标题栏。
- **配色：** 深色玻璃为主，单一蓝色强调；状态色克制——青(正常)→黄(警告)→红(严重)渐变。
- **基调：** 专业开发者工具风，数据优先，避免幼稚的大按钮与过量 emoji。

## 4. 产品形态（四种载体）

### 4.1 菜单栏图标（常驻）
- 右上角火箭图标，实时显示 `CPU% · 温度`。
- 过热（温度超阈值）时数字变红。
- 点击展开菜单栏面板。

### 4.2 菜单栏弹出面板
- CPU / 内存 / Swap 三条进度条 + 数值。
- CPU/GPU 温度（样式三：数字+迷你曲线）。
- 「🚀 一键加速」按钮。

### 4.3 桌面悬浮窗（always-on-top）
- 可拖动、始终置顶、半透明，可收起成小球。
- 环形 CPU 仪表 + 温度数字（CPU温/GPU温）+ 内存。
- 适合长时间挂在桌面角落观察。

### 4.4 主窗口（4 个 Tab）
- **总览：** CPU 占用环 + CPU 温度 + GPU 温度三环并排；CPU 负载趋势曲线（最近 60s）；内存/Swap 概况。
- **进程：** 按 CPU 排序的进程列表，每行可「结束进程」（二次确认）。
- **优化：** 一键加速面板（见 §6）。
- **历史：** 过去 24 小时 CPU 与温度曲线，标注发热高峰及其疑似来源。

## 5. 温度计

### 5.1 显示样式
统一采用**样式三：数字 + 迷你曲线**。展示两路：
- 🌡 **CPU 温度** — 取自性能核区域传感器。
- 🌡 **GPU 温度** — 取自 GPU 区域传感器。

> 说明：M1–M5 均为 SoC 单芯片，CPU 与 GPU 在同一硅片，两路温度取自芯片不同区域传感器，数值接近但不相同——这是真实物理情况，UI 上如实呈现。

### 5.2 跨芯片兼容策略（M1–M5）

底层统一走 `IOHIDEventSystemClient`（M1–M5 通用，无需 sudo/kext）。难点在于**各代芯片传感器命名不同且 Apple 不公开文档**。采用**三层兜底**：

1. **运行时动态枚举**：列出芯片上全部温度传感器，不预设名字。
2. **关键词模式匹配 + 聚合**：按传感器名关键词归类（如含 CPU/pACC/eACC → CPU 温度；含 GPU → GPU 温度），同类多传感器取最大值（或平均值，可配置）。
3. **分代精确映射表**：对 M1/M2/M3/M4 已知传感器名做精确映射（精度最高）；命中失败回退到第 2 层。
4. **优雅降级**：未知新芯片（如尚未适配的 M5）若全部匹配失败，**显示"温度暂不支持"，绝不编造假数据**。
5. **芯片识别**：通过 `sysctl machdep.cpu.brand_string` 判定代次，加载对应映射表。

## 6. 一键加速

### 6.1 交互流程（三步）
1. **待机**：展示当前健康分与可回收资源估算。
2. **扫描结果**：列出可优化项的勾选清单，标注预计收益、风险、是否可逆；默认勾选安全项，危险项需用户确认。
3. **执行结果**：以**日志形式**呈现每步结果（成功/跳过/释放量），并显示健康分前后对比。不做庆祝式弹窗。

### 6.2 四个动作

| 动作 | 实际执行 | 风险 | 可逆 | 权限 |
|------|----------|------|------|------|
| 释放不活跃内存 | `purge` 系统调用，回收 inactive 内存 + 清磁盘缓存 | 低 | — | 需一次管理员授权 |
| 结束高占用进程 | 仅 `kill` 用户勾选的进程 | **未保存内容会丢**，逐个二次确认 | 否 | 普通 |
| 清理用户缓存 | 删 `~/Library/Caches` 等可重建文件，不碰系统目录 | 低 | 缓存自动重建 | 普通 |
| 降低图形合成负载 | 开启「减少透明度 / 减弱动效」辅助功能开关 | 无 | **完全可逆，可一键还原** | 普通 |

### 6.3 安全原则
- 透明：每个动作明示真实命令，不做黑箱。
- 危险动作（结束进程、purge）必须二次确认 / 授权。
- 所有可逆动作提供「还原」。

## 7. 诊断引擎

在「总览」与一键加速「扫描」阶段共用一套规则引擎，根据实时指标输出问题清单与建议，例如：
- Swap 使用率 > 阈值 → "内存耗尽，建议释放内存 / 关闭高占用 App"。
- 某进程 CPU 持续 > 阈值 → "X 进程占用过高，建议重启该应用"。
- 开机时长 > N 天 → "建议重启释放资源"。
- WindowServer 高占用 + 外接高分屏缩放 → "外接屏 HiDPI 缩放导致图形负载，建议改原生分辨率 / 降图形负载"。

每条规则 = 触发条件 + 文案 + 关联的处理动作（可直接跳到一键加速对应项）。

## 8. 模块划分（单一职责）

- **SensorKit**：传感器与系统指标采集。对外暴露 `cpuUsage / memory / swap / temperatures(cpu,gpu) / loadAvg / processes`。内部封装 IOKit/mach/sysctl 调用与跨芯片温度映射。可独立测试（喂入模拟传感器数据）。
- **DiagnosisEngine**：输入一份指标快照，输出问题清单（纯函数，易测）。
- **OptimizationService**：执行四个加速动作，每个动作是独立可测单元，返回结构化结果（释放量/状态）。
- **UI 层**：
  - `MenuBarController`（AppKit）：菜单栏图标 + 弹出面板。
  - `FloatingWidget`（AppKit NSPanel）：桌面悬浮窗。
  - `MainWindow`（SwiftUI）：四个 Tab。
  - 共享 `GlassBackground`（NSVisualEffectView 封装）与温度计、环形仪表等可复用视图组件。
- **AppState**：可观察的全局状态（采样定时器驱动），各 UI 订阅。

边界原则：UI 只读 AppState，不直接调系统 API；所有系统交互收敛到 SensorKit / OptimizationService，便于测试与替换。

## 9. 错误处理与降级

- 温度读不到 → 显示"温度不可用"，其余指标正常工作。
- `purge` 授权被拒 → 跳过该步并在日志标注，不影响其它动作。
- 结束进程失败（权限/已退出）→ 日志标注 skipped + 原因。
- 采样异常 → 保留上一次有效值并标记 stale，不崩溃。

## 10. 测试策略

- **SensorKit**：注入模拟数据，验证 CPU%/内存/Swap 计算与温度聚合逻辑；针对 M1–M4 各自的传感器名样本验证映射；未知芯片样本验证降级到"不可用"。
- **DiagnosisEngine**：给定指标快照断言输出的问题清单（纯函数全覆盖边界阈值）。
- **OptimizationService**：用可注入的命令执行器（mock）验证动作编排、二次确认分支、失败跳过、还原逻辑——不在测试中真的 kill/purge。
- **UI**：关键视图快照测试（可选）。

## 11. 里程碑（建议顺序）

1. SensorKit 基础指标（CPU/内存/Swap/负载）+ 单测。
2. 温度读取 + 跨芯片映射 + 降级 + 单测。
3. 主窗口「总览」页（毛玻璃 + 温度计样式三）。
4. 菜单栏图标 + 弹出面板。
5. 进程页 + 结束进程。
6. DiagnosisEngine + 总览诊断卡。
7. OptimizationService + 优化页（一键加速三步流程）。
8. 桌面悬浮窗。
9. 历史页（数据留存 + 曲线）。

## 12. 待确认 / 风险

- `IOHIDEventSystemClient` 是私有框架，**无法上架 Mac App Store**（仅自用/直接分发 ok）。若未来要上架，温度功能需另寻方案或砍掉。
- M5 传感器名未知，发布时若 M5 已上市需补真机适配，否则走降级显示。
- macOS 各版本 vibrancy 行为略有差异，需在目标系统版本上验证。
